<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /firms/[id] route param | User-supplied `id` path segment reaches a DB lookup |
| browser → runResearch server action | Refresh button triggers a server-side research job |
| DB findings/procurement → rendered HTML | Cached AI/OCDS strings (summary, sourceUrl, title) render in the profile |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | `/firms/[id]` route param | mitigate | getFirmProfile uses a parameterised Drizzle `eq(firms.id, id)` lookup (no string interpolation); unknown id → `notFound()` 404, never a partial render |
| T-03-02 | Injection (XSS) | findings-by-topic / citation-panel rendering finding.summary, sourceUrl, sourceTitle | mitigate | Render all DB strings as React text children (auto-escaped); never `dangerouslySetInnerHTML`; citation `<a href>` uses the stored URL only in href, displayed text is truncated/escaped |
| T-03-03 | Injection (URL) | citation link `<a href={finding.sourceUrl}>` | mitigate | Render link only for real findings (sourceUrl !== "not-found"); add `rel="noopener noreferrer"` and `target="_blank"` so a malicious source URL cannot reach back into the app context |
| T-03-04 | Elevation/abuse | runResearch via FirmRefreshAction | accept | Single-user local tool, no auth surface; runResearch already guards firm existence + CH-number presence server-side |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new package installs in this plan (all primitives already in package.json); if any install is proposed during execution, stop and add a blocking human-verify checkpoint |

No high-severity threats. T-03-02 and T-03-03 are the load-bearing mitigations and are enforced by default React escaping + explicit link gating.
</threat_model>
