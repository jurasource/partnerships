<objective>
Deliver the cross-firm comparison dashboard vertical slice: extend the existing read-only `ComparisonTable` at `/` into a filterable, sortable comparison with clickable firm-name links (to the new profiles), research status, contract count, a capability-tag filter bar, and a per-row Refresh Research action.

Purpose: DASH-01/02/03/04 — give the user one screen to compare all firms and act on them.

</objective>

## Phase Goal (user story)

**As a** bid/consortium planner, **I want to** compare all firms in one table I can filter by capability, sort by any column, and refresh per firm, **so that** I can quickly shortlist which firms to investigate or team with.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → runResearch server action | Per-row Refresh triggers a server-side research job |
| client filter/sort state → rendered rows | Client-side TanStack filtering of firm rows |
| DB firm/contract data → rendered HTML | Cached firm + contract-count values render in the table |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Injection (XSS) | comparison-table cells rendering firm.canonicalName + tags | mitigate | All values render as React text children (auto-escaped); firm-name link uses `href={`/firms/${id}`}` with the DB id only, never user free text in the path beyond the stored UUID |
| T-03-06 | Tampering | firm-name Link target /firms/[id] | mitigate | id comes from the DB row (`row.original.id`), a generated UUID, not client input; the profile route re-validates via getFirmProfile + notFound() |
| T-03-07 | Elevation/abuse | runResearch via per-row FirmRefreshAction | accept | Single-user local tool, no auth; runResearch guards firm existence + CH-number server-side and is idempotent (enqueues one job) |
| T-03-08 | DoS | rapid repeated Refresh clicks | mitigate | Button disabled while running (per-row state); each click enqueues at most one job; acceptable for a single local user |
| T-03-SC | Tampering | npm/pip/cargo installs | mitigate | No new package installs in this plan (TanStack Table, lucide, sonner already in package.json); any proposed install during execution → stop and add a blocking human-verify checkpoint |

No high-severity threats.
</threat_model>
