<objective>
Build the trustworthy UK data layer: thin typed clients for Companies House, Contracts Finder, and Find a Tender; a shared OCDS adapter that normalises both procurement sources into one shape and dedupes by `ocid` at write time; a SQLite-backed job-queue skeleton; and the per-firm refresh slice that wires it all together. Also activates the "Search CH" button in the Add/Edit Firm dialog.

Purpose: This is the data foundation the whole project sits on (ARCHITECTURE build-order #1). It satisfies DATA-01..05 and makes the per-firm refresh control (UI-SPEC) real, while leaving the Phase 2 research worker a clean enqueue/claim/status contract (D-07, D-08).

Output: 3 API clients + a rate-limited fetch helper, the OCDS normalise/dedup adapter, the job queue, a `refreshFirm` server action, the firm-row refresh control, and the live CH search field.

## Phase Goal

**As a** bid-planning analyst, **I want to** refresh a firm and pull its real Companies House ownership and UK procurement records (deduped, matched by company number) into the local cache, **so that** I have verifiable structured data to research and compare.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → Companies House / CF / FTS APIs | Outbound fetches to fixed GOV.UK hosts; CH carries the secret API key |
| external API JSON → OCDS adapter | Untrusted third-party JSON parsed and normalised into the cache |
| browser → refreshFirm / CH-search server action | User triggers server-side outbound fetch (SSRF surface) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-08 | Information Disclosure | COMPANIES_HOUSE_API_KEY | mitigate | Key read only in server-side clients (`http.ts`/`companies-house.ts`); Search CH and refresh invoked via server actions — key never imported into a client component or logged |
| T-01-09 | Server-Side Request Forgery | refreshFirm / CF/FTS/CH fetches | mitigate | Client base URLs are hard-coded constants to fixed GOV.UK hosts; only the CH *number* and search *query* are user-supplied and are URL-encoded into fixed paths — no user-controlled host/scheme reaches `fetch` |
| T-01-10 | Tampering | OCDS adapter parsing third-party JSON | mitigate | Zod-validate API responses; never `Object.assign`/spread untrusted keys onto prototypes; normalise into typed columns only (prevents prototype pollution); tolerate empty/implausible fields without trusting them |
| T-01-11 | Denial of Service | rate limits / runaway fetch | mitigate | `rateLimitedFetch` enforces concurrency cap + 429/5xx backoff with retry cap; cache-first means no re-fetch without explicit refresh (Pitfall 6) |
| T-01-12 | Repudiation | data provenance | mitigate | Store `sourceApi` + full `rawJson` per record (D-10) so every cached fact is auditable back to its source payload |
</threat_model>
