<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → Server Action (createFirm) | Untrusted form input (firm name, CH number, tags) crosses into server-side DB write |
| app → SQLite file (./data/app.db) | Local file write; path is env-configurable |
| app → Companies House (env key) | API key stored in .env.local, used server-side only (live lookup lands in Plan 03; key provisioned now) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | createFirm server action | mitigate | Validate all input with Zod (canonicalName non-empty, capabilityTags ∈ CapabilityTag union); insert via Drizzle parameterised queries — no raw SQL string concatenation (prevents SQL injection) |
| T-01-02 | Information Disclosure | COMPANIES_HOUSE_API_KEY | mitigate | Key only in .env.local (git-ignored) and read server-side; never imported into a client component; `.env.example` carries no real value |
| T-01-03 | Tampering | DATABASE_PATH file write | accept | Single-user local-first tool; path is developer-controlled env var, not user-supplied at runtime — no untrusted file-write surface |
| T-01-04 | Tampering | seed.ts JSON / aliases parsing | mitigate | Seed data is developer-authored, not untrusted input; JSON columns parsed only from app-written rows. No third-party JSON parsed in this plan (prevents prototype pollution) |
| T-01-SC | Tampering | npm/shadcn installs | mitigate | Task 1 blocking-human legitimacy gate before any install (no audit table in research → all [ASSUMED]); packages verified on npmjs.com |
</threat_model>
