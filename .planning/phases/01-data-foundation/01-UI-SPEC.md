# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Phase scope note:** Phase 1 delivers the app shell (persistent left sidebar nav), the Dashboard landing view (firm comparison table — read-only in this phase), and the configuration screens (Firms, Topics) with add/edit Dialogs. It does NOT render AI findings or the research dashboard (Phases 2–3). This contract governs the shell + config UI only; later phases extend it.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui (CLI-installed during execution) |
| Preset | New York style, neutral base color, CSS variables enabled |
| Component library | radix (shadcn primitives) + TanStack Table v8 (headless data grid) |
| Icon library | lucide-react |
| Font | Geist Sans (Next.js default) for UI; Geist Mono for CH numbers / OCDS IDs / tabular data |

**shadcn init command (execution):** `npx shadcn@latest init` → select New York, neutral, CSS variables = yes.

**Components to install in Phase 1:** `button`, `dialog`, `input`, `label`, `badge`, `table`, `sidebar`, `tabs`, `select`, `sonner` (toast), `skeleton`, `tooltip`, `dropdown-menu`, `separator`.

## Layout

| Region | Contract |
|--------|----------|
| Shell | Two-column app shell: persistent left sidebar + main content area. Uses shadcn `sidebar` primitive (`SidebarProvider` + `SidebarInset`). |
| Sidebar width | 256px expanded, 56px collapsed (icon-only rail). Collapsible via header toggle (D-04, "specifics" nice-to-have — implement the toggle). |
| Sidebar contents | App title/logo block (top), nav links (Dashboard, Firms, Topics), with Analysis/Consortium reserved as disabled/hidden placeholders for later phases. Active link highlighted with secondary surface + accent left indicator. |
| Landing route | `/` renders the Dashboard (firm comparison table) — primary read view (D-05). |
| Main content max width | Full available width (no centered max-width column — this is a data-dense dashboard). Content padding: 24px (`lg`) horizontal, 24px top. |
| Page header | Each screen has a header row: page title (Heading) on the left, primary CTA button on the right. |
| Firms / Topics views | Page header + TanStack Table data grid below. Add/edit opens in a shadcn `Dialog` overlaying the list (D-06). |
| Responsive | Desktop-first (this is a local power-user tool). Sidebar auto-collapses to icon rail below 1024px. No mobile layout target for Phase 1. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inner padding, inline chip spacing |
| sm | 8px | Compact element spacing, form field internal gaps, table cell padding (vertical) |
| md | 16px | Default element spacing, gap between form fields, table cell padding (horizontal) |
| lg | 24px | Page content padding, dialog padding, section padding |
| xl | 32px | Gaps between major content blocks |
| 2xl | 48px | Empty-state vertical padding, major section breaks |
| 3xl | 64px | Reserved for page-level spacing (unused in Phase 1) |

Exceptions: Sidebar collapsed rail icon hit targets are 40px (between sm and lg) to meet comfortable click targets; this is an intentional component-level exception, not a token.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Display | 28px | 600 (semibold) | 1.2 — page titles (e.g. "Firms", "Topics", "Dashboard") |
| Heading | 20px | 600 (semibold) | 1.2 — dialog titles, section headings, empty-state headings |
| Body | 16px | 400 (regular) | 1.5 — default text, form labels values, dialog body copy |
| Label | 14px | 400 (regular) | 1.4 — table cells, form field labels, badge text, helper/meta text |

Weights: exactly two — regular (400) and semibold (600).
Sizes: exactly four — 28 / 20 / 16 / 14.
Monospace exception: Companies House numbers, OCDS `ocid` values, and numeric contract values render in Geist Mono at the Label size (14px/400) for column alignment and scannability — this is a font-family swap, not a new type scale entry.

## Color

Light mode is the primary (and only Phase 1) theme. Values are the shadcn neutral base palette plus a declared blue accent.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#ffffff` (background) / `neutral-50 #fafafa` | Page background, main content surface |
| Secondary (30%) | `neutral-100 #f5f5f5` / card `#ffffff` w/ `neutral-200 #e5e5e5` borders | Sidebar surface, cards, table header row, dialog surface, input fields |
| Accent (10%) | `blue-600 #2563eb` | See reserved list below |
| Destructive | `red-600 #dc2626` | Destructive actions and error states only |

Accent (`blue-600`) reserved for:
- Primary CTA buttons ("Add Firm", "Add Topic", dialog primary submit)
- Active sidebar nav item indicator
- Focus rings on interactive elements
- Selected-row / selected-state affordances in tables
- Inline "Search CH" action button

Accent is NOT used for: body text, icon defaults, borders, table content, or decorative fills.

**Capability tag badge colors** (categorical, low-saturation tints on neutral/outline badge base — these are data encodings, not the UI accent, and are exempt from the 10% accent budget):

| Category | Tint | Badge style |
|----------|------|-------------|
| Nuclear | amber (`amber-100` bg / `amber-700` text) | soft tint badge |
| Infrastructure | sky (`sky-100` bg / `sky-700` text) | soft tint badge |
| Construction | violet (`violet-100` bg / `violet-700` text) | soft tint badge |
| Uncategorised / other | neutral (`neutral-100` bg / `neutral-600` text) | outline/neutral badge |

Tag tints stay desaturated so they read as data labels, never compete with the blue CTA accent.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — Firms screen | **Add Firm** |
| Primary CTA — Topics screen | **Add Topic** |
| Dialog primary submit — new firm | **Add Firm** |
| Dialog primary submit — edit firm | **Save Changes** |
| Dialog primary submit — new/edit topic | **Add Topic** / **Save Changes** |
| Secondary action — CH lookup | **Search CH** |
| Empty state heading — Firms | **No firms yet** |
| Empty state body — Firms | "Add a firm to start building your intelligence list. You can enter a Companies House number directly or search for it." (primary action: **Add Firm**) |
| Empty state heading — Topics | **No research topics yet** |
| Empty state body — Topics | "Define the questions you want answered about each firm. Topics drive the research run in the next phase." (primary action: **Add Topic**) |
| Empty state heading — Dashboard | **No firm data to compare** |
| Empty state body — Dashboard | "Add firms on the Firms screen to populate the comparison table." (link to Firms) |
| Error state — CH search failure | "Couldn't reach Companies House. Check your connection and try again, or enter the company number manually." |
| Error state — data API failure (CF/FTS fetch) | "Couldn't load procurement data for this firm. The source may be temporarily unavailable — try refreshing this firm." |
| Loading state | Skeleton rows in tables; per-firm refresh shows an inline spinner on the row's refresh control. |
| Destructive confirmation — Delete firm | **Delete firm?** "Remove [Firm name] and its cached procurement and research data? This can't be undone." Confirm button: **Delete** (destructive/red). |
| Destructive confirmation — Delete topic | **Delete topic?** "Remove [Topic name]? Findings tied to this topic will be removed in future research runs." Confirm button: **Delete** (destructive/red). |
| Save success toast | "Firm added" / "Changes saved" / "Topic added" (sonner, neutral, auto-dismiss). |

Note: even though the 12 firms and 7 topics are pre-seeded (D-01), empty states are specified because a user can delete all entries or start a fresh DB. Empty states must render correctly with zero rows.

## Interaction

| Pattern | Contract |
|---------|----------|
| Add / Edit firm | shadcn `Dialog`. List stays visible behind a dim overlay (D-06). Form fields: canonical name, aliases, Companies House number (with **Search CH** button → results in a `Select`/list, auto-fills number on pick, D-03), capability tags. |
| Add / Edit topic | shadcn `Dialog`, same modal pattern. Fields: topic name, description/question text. |
| CH search | **Search CH** triggers the `/search/companies` query; results render as a selectable list inside the dialog; selecting a result auto-fills the CH number field (D-03). Manual entry remains the primary path and is always editable (D-02). |
| Delete | Confirmation via `AlertDialog` (destructive variant). No silent deletes. |
| Table interaction | TanStack Table: column sort (click header), multi-column filter (capability-tag filter is the priority filter). Row hover = `neutral-50` highlight. Numbers/IDs right-aligned in mono. |
| Sidebar collapse | Toggle in sidebar header collapses to 56px icon rail; state persists for the session. Tooltips show link labels when collapsed. |
| Focus & keyboard | All interactive elements keyboard-reachable; visible `blue-600` focus ring (2px). Dialogs trap focus and close on Esc. |
| Per-firm refresh | Each firm row exposes a refresh control (icon button) that re-fetches CH/CF/FTS data; shows inline spinner while running and a success/error toast on completion. |
| Form validation | Inline error text below field (Label size, `red-600`). Required: canonical name + CH number for firms; name for topics. Submit disabled until required fields valid. |
