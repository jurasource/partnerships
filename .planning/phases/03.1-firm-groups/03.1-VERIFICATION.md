### Gaps Summary

Two confirmed code gaps, both sharing the same root cause — `router.refresh()` was omitted from two client components after successful server action mutations:

**Gap 1 — GroupFormDialog (group-form-dialog.tsx):** After a successful `createGroup` call, the dialog closes but the /groups RSC is not refreshed. The new group is invisible in the list until the user navigates away and back. The fix is a one-liner: import `useRouter` from `next/navigation` and call `router.refresh()` after `toast.success`.

**Gap 2 — GroupsTable (groups-table.tsx):** After a successful `deleteGroup` call, the deleted row remains in the table until the user navigates away. The fix is the same pattern.

Both gaps were independently identified in the code review (03.1-REVIEW.md WR-01 and WR-02) and confirmed here by code inspection — neither file contains any `router` import or `router.refresh()` call.

The gaps do not affect the data layer (schema, types, actions are all correct), the /groups/[id] detail page (GroupDetailClient has router.refresh on all mutations), or the firms table (server-rendered data loads fresh on every RSC fetch).
