## What Was Built

### Schema additions (src/db/schema.ts)

- `groups` table: `id` (text PK, `$defaultFn(crypto.randomUUID)`), `name` (text notNull), `createdAt` (timestamp mode:"string" defaultNow), `updatedAt` (timestamp mode:"string" defaultNow)
- `firmGroups` table: `firmId` (text FK → firms.id, CASCADE), `groupId` (text FK → groups.id, CASCADE), composite PK on `[firmId, groupId]`
- Added `primaryKey` import from `drizzle-orm/pg-core`

### Type exports (src/lib/types.ts)

- `export type Group = InferSelectModel<typeof groups>`
- `export type FirmGroup = InferSelectModel<typeof firmGroups>`

### Server actions (src/lib/actions/group-actions.ts)

| Action | Contract | Notes |
|--------|----------|-------|
| `createGroup(name)` | `{ ok: true, id } \| { ok: false, error }` | Validates via Zod NameSchema; rejects whitespace |
| `updateGroup(id, name)` | `{ ok: boolean, error? }` | Sets name + updatedAt ISO string |
| `deleteGroup(id)` | `{ ok: boolean, error? }` | Cascade cleans firmGroups rows via FK |
| `addFirmToGroup(firmId, groupId)` | `{ ok: boolean, error? }` | `onConflictDoNothing` — idempotent |
| `removeFirmFromGroup(firmId, groupId)` | `{ ok: boolean, error? }` | Deletes exact junction row |

All actions call `revalidatePath("/groups")`; delete/add/remove also call `revalidatePath("/firms")`.

### Database (Postgres)

Both `groups` and `firm_groups` tables created in Postgres. Verified by introspection: correct columns, composite PK on firm_groups, CASCADE delete on both FKs.

## Deviations from Plan

### Auto-handled Issues

**1. [Rule 3 - Blocking] drizzle-kit push failed in non-TTY environment**
- **Found during:** Task 2
- **Issue:** `drizzle-kit push` triggered `promptNamedWithSchemasConflict` because the DB contains extra tables (`collaboration_records`, `conflict_pairs`, `ownership_records`, etc.) not present in the schema. drizzle-kit requires a TTY to prompt "keep or delete these tables?" but Claude Code runs in a non-TTY context.
- **Fix:** Applied the schema changes directly via raw SQL using the `postgres` package with `CREATE TABLE IF NOT EXISTS` — identical DDL to what drizzle-kit would have generated. Both tables created with correct constraints.
- **Files modified:** None (DB-only change)
- **Impact:** None — tables are correctly created; `drizzle-kit push` from a terminal will show no pending changes.

**2. [Rule 1 - Bug] Test assertion `expect(mockDb.insert).toBeUndefined()` failed**
- **Found during:** Task 1 GREEN phase (first test run)
- **Issue:** The shared `mockDb` object retains properties set in earlier tests within the same describe block. After `resetAllMocks()`, the `insert` property on the object reference persists.
- **Fix:** Changed assertion to `const mockInsert = vi.fn(); mockDb.insert = mockInsert; expect(mockInsert).not.toHaveBeenCalled()` — tracks the specific mock function rather than checking for undefined.
- **Files modified:** src/lib/actions/group-actions.test.ts
