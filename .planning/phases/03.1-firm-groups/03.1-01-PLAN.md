    - updateGroup(id, "New Name") sets name + updatedAt and returns { ok: true }
    - deleteGroup(id) deletes the group row and returns { ok: true }
    - addFirmToGroup(firmId, groupId) inserts a firmGroups row; calling twice for the same pair does not throw (onConflictDoNothing)
    - removeFirmFromGroup(firmId, groupId) deletes the matching firmGroups row and returns { ok: true }

  <action>
    In `src/db/schema.ts`, import `primaryKey` from "drizzle-orm/pg-core" (alongside existing pgTable/text/timestamp imports). Add two tables after the existing `firms` table:

    `groups` = pgTable("groups", { id: text("id").primaryKey().$defaultFn(() => crypto.randomUUID()), name: text("name").notNull(), createdAt: timestamp("created_at", { mode: "string" }).notNull().defaultNow(), updatedAt: timestamp("updated_at", { mode: "string" }).notNull().defaultNow() }).

    `firmGroups` = pgTable("firm_groups", { firmId: text("firm_id").notNull().references(() => firms.id, { onDelete: "cascade" }), groupId: text("group_id").notNull().references(() => groups.id, { onDelete: "cascade" }) }, (table) => [primaryKey({ columns: [table.firmId, table.groupId] })]). The cascade on BOTH FKs ensures deleting a firm OR a group cleans up junction rows.

    In `src/lib/types.ts`, add `groups` and `firmGroups` to the schema import and export `export type Group = InferSelectModel<typeof groups>;` and `export type FirmGroup = InferSelectModel<typeof firmGroups>;`.

    Create `src/lib/actions/group-actions.ts` with `"use server";` at top, mirroring `firm-actions.ts` structure exactly:
    - Import `revalidatePath` from "next/cache", `z` from "zod", `eq`, `and` from "drizzle-orm", `db` from "@/db/client", `groups`, `firmGroups` from "@/db/schema".
    - Define `const NameSchema = z.object({ name: z.string().trim().min(1, "Group name is required") });`
    - `createGroup(name: string)`: validate via NameSchema; on failure return { ok: false, error: firstIssue }; insert into `groups` with `.returning({ id: groups.id })`; revalidatePath("/groups"); return { ok: true, id }. Wrap DB work in try/catch returning a friendly error and console.error on failure (match firm-actions copy style).
    - `updateGroup(id: string, name: string)`: guard empty id; validate name; `db.update(groups).set({ name, updatedAt: new Date().toISOString() }).where(eq(groups.id, id))`; revalidatePath("/groups"); return { ok: true }.
    - `deleteGroup(id: string)`: guard empty id; `db.delete(groups).where(eq(groups.id, id))` (firmGroups rows cascade via FK); revalidatePath("/groups"); revalidatePath("/firms"); return { ok: true }.
    - `addFirmToGroup(firmId: string, groupId: string)`: guard both ids; `db.insert(firmGroups).values({ firmId, groupId }).onConflictDoNothing()`; revalidatePath("/groups"); revalidatePath("/firms"); return { ok: true }.
    - `removeFirmFromGroup(firmId: string, groupId: string)`: guard both ids; `db.delete(firmGroups).where(and(eq(firmGroups.firmId, firmId), eq(firmGroups.groupId, groupId)))`; revalidatePath("/groups"); revalidatePath("/firms"); return { ok: true }.

    Write the test FIRST in `src/lib/actions/group-actions.test.ts` following firm-actions.test.ts mocking exactly: `vi.mock("@/db/client", () => ({ db: {}, sql: {} }))`, `vi.mock("next/cache", () => ({ revalidatePath: vi.fn() }))`. Cover each behavior bullet above. For addFirmToGroup idempotency, assert the chain ends in `.onConflictDoNothing()` (mock returns resolved without throw). Do NOT place code fences in this PLAN; write the actual code in the source files.
