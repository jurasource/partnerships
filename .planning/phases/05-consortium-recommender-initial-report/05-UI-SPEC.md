### CapabilityMixInput

Three stepper counter groups arranged in a row (`flex gap-6`):

- Each group: label (text-xs font-semibold uppercase) + row of `−` button, count value, `+` button
- Buttons: `variant="outline" size="icon"` — 44px minimum touch target
- Count display: `text-lg font-semibold font-mono w-8 text-center`
- Minimum count per tag: 0; maximum: 5
- Count of 0 renders the count as `text-neutral-300` to signal inactive
- Total mix must be >= 1 to enable "Get Recommendation" button; if 0, button is disabled with `opacity-50 cursor-not-allowed`

### WeightSliders

Four labeled slider rows in a `flex flex-col gap-6`:

| Signal label | Slider ID | Default | Range |
|-------------|-----------|---------|-------|
| Prior partnerships | `weight-partnerships` | 25 | 0–100 |
| UK ownership | `weight-uk-ownership` | 25 | 0–100 |
| Contract relevance | `weight-contract-relevance` | 25 | 0–100 |
| Risk profile | `weight-risk-flags` | 25 | 0–100 |

- Each row: label left, current value right (`font-mono text-xs text-neutral-500`)
- Slider: shadcn `Slider` default track/thumb styling
- Weights do not need to sum to 100 — the algorithm normalises them server-side

### LockFirmsSection

- List all firms alphabetically: checkbox + firm name + capability tag badges inline
- Checkboxes use shadcn label+input pattern (accessible)
- Checked state: firm name renders `font-medium text-neutral-900`; unchecked: `text-neutral-600`
- Checked firms display a `Lock` lucide icon (h-3 w-3) inline after the name

### FirmSubCard

Each recommended firm renders as a Card within the recommendation:

```
<Card class="bg-white border-neutral-100 p-4">
  <div class="flex items-start justify-between gap-3">

    <div class="flex flex-col gap-1.5">
      <span class="text-sm font-semibold text-neutral-900">  {firm.canonicalName}
      <div class="flex items-center gap-1.5 flex-wrap">
        {capabilityTagBadges}   (amber/sky/violet — existing pattern)
        {ownershipBadge}        (green "UK" or orange ISO country code)
        {nsiBadge?}             (amber "NSI" — only when foreign-owned)
      </div>
    </div>

    <div class="flex items-center gap-2 shrink-0">
      {conflictBadge?}          (red "Conflict" — only when conflict with team member)
      {riskBadge}               (red/amber/neutral count of risk flags)
    </div>
  </div>

```

- Conflict badge renders only when a `conflictPairs` row exists between this firm and another firm in the same recommended team
- NSI badge renders only when `ownershipRecords.ukIncorporated === false`
- Risk badge count: total number of `riskFlags` rows for this firm; color driven by highest severity present

### ScoreBreakdown

Collapsible section inside the primary recommendation card:

- Trigger: text-xs text-neutral-500 underline "View reasoning" / "Hide reasoning"
- Content: `<table>` with columns: Firm | Partnerships | UK Ownership | Contract Relevance | Risk Profile | Total
- All score values: `font-mono text-xs`
- Conflict exclusions shown as a separate paragraph: "The following pairs were excluded: {Firm A} + {Firm B} — {conflictType}"
- Source citation per signal line: "Source: {table name} (last updated {date})" in `text-xs text-neutral-400`

## Interaction Contract

### Capability mix counter (CONS-01)

- `+` increases count; `−` decreases count; minimum is 0; maximum is 5
- Count is stored in component state (`useState` per tag)
- Zero total = "Get Recommendation" button is disabled; `aria-disabled="true"` on button
- No URL state in Phase 5 MVP (client state only)

### Weight sliders (D-06, CONS-02)

- All four sliders default to 25 on page load
- Sliders are inside a collapsed accordion ("Scoring weights") by default — user must expand to change
- Value label updates live on drag
- Weights are passed as-is in the API request body; server normalises to 0–1 range

### Lock firms (D-07, D-08, CONS-05)

- Lock section is a collapsed accordion ("Lock firms (optional)") by default
- Checking a firm adds its ID to `lockedFirmIds` state
- Locked firms display a `Lock` icon
- After seeing a result, user may lock firms from the result and click "Lock these firms & recompute" — this re-submits the same request with `lockedFirmIds` updated from the selected firms in the primary result card
- The "Lock these firms & recompute" button calls the same API route and re-renders the result in place

### "Get Recommendation" submit (D-03)

- Button click POSTs to `/api/recommend` with current state (mix, lockedFirmIds, weights)
- During request: button shows `Loader2` icon animated (`animate-spin`), text changes to "Computing...", button is disabled
- On success: result section renders below the submit button (no page navigation)
- On error: sonner toast "Could not compute recommendation. {server error message}." with action "Try again"

### Recompute (D-08, CONS-05)

- "Lock these firms & recompute" button appears in primary recommendation card footer after first result
- Locks all three firms from the primary result into `lockedFirmIds`, re-POSTs to `/api/recommend`
- Result panel updates in place (same loading pattern as initial submit)
- "Reset" link (text-xs text-blue-600 underline) appears alongside "Recompute" to clear all locks and return to default state

### No valid team state

- Rendered in place of the result section
- Uses same empty-state layout pattern as existing pages: centered icon + heading + body + action

### `/report` page

- Server-rendered on load; no interactive controls
- If no data exists (pipeline not run): show no-valid-team state with body copy directing user to run research
- No "Recompute" button on `/report` — it always shows the default 1+1+1 result

### Navbar update

- "Analysis" placeholder nav item: becomes a live link `href="/analysis"` with `BarChart3` icon (Phase 4 task; carry if not yet done by Phase 4-04)
- "Consortium" placeholder nav item: replace with live link `href="/recommend"` using `Users` icon, label "Recommend"
- Add new nav item: `href="/report"`, `FileText` lucide icon, label "Report"
- Active state: `bg-white/10 text-white` (existing active pattern)

## Route Architecture

| Route | Component type | Notes |
|-------|---------------|-------|
| `/recommend` | Client component (`"use client"`) | Stateful: mix counters, locks, weights, result. POSTs to `/api/recommend`. |
| `/report` | Server component (RSC) | Calls `/api/recommend` at render; no client state. |
| `/api/recommend` | Next.js Route Handler (POST) | Rules-based algorithm; returns typed recommendation object. No mutation of DB. |
| `/analysis` | Server component (existing or Phase 4-04) | Phase 4 task — sidebar nav link becomes live in this phase if Phase 4-04 complete. |
