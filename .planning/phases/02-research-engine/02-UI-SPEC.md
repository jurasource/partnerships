**Accent reserved for — explicit list:**
Phase 2 introduces two new accent usages, both using existing Phase 1 ad-hoc color patterns (semantic overrides via Tailwind utility classes, not new CSS variables):

1. **"Run Research" trigger button** — `text-neutral-600 hover:text-blue-700 hover:bg-blue-50` — consistent with the existing `FirmRowRefresh` hover state pattern. Uses blue as the "action" accent.
2. **"running" job status badge** — `bg-blue-100 text-blue-700 border-blue-200` — same blue family as the trigger hover, signals active state.
3. **"done" job status badge** — `bg-green-100 text-green-700 border-green-200` — success signal only used for completed research jobs.
4. **"failed" job status badge** — `bg-red-100 text-red-700 border-red-200` — failure signal. Uses the red family (not `--destructive` token, which is for destructive actions, not error states).
5. **"Stale" staleness badge** — `bg-amber-100 text-amber-700 border-amber-200` — warning signal for findings older than 7 days. Consistent with the existing `Nuclear` capability tag badge color.
6. **Progress bar fill** — `bg-blue-600` (or shadcn `progress` default primary) — the "N/7 topics complete" progress indicator.

## Component Inventory

New components and patterns introduced in Phase 2. All use existing shadcn primitives.

### ResearchTriggerButton
**Location:** `src/components/firms/firm-row-research.tsx`
**Pattern:** Extends `FirmRowRefresh` pattern — ghost icon button (h-8 px-2) with `FlaskConical` or `Search` lucide icon, tooltip, and inline "Researching…" label while running. Uses `text-neutral-600 hover:text-blue-700 hover:bg-blue-50` colors.
**States:**
- Idle: icon only, tooltip "Run AI research for {firmName}"
- Running: icon spins (`animate-spin`), tooltip "Researching… (N/7 topics)", disables the button, shows inline "Researching…" pulse text
- Disabled (no CH number): icon muted (`text-neutral-300`), tooltip "Add a Companies House number before running research"

### JobStatusBadge
**Location:** `src/components/research/job-status-badge.tsx`
**Pattern:** shadcn `Badge` with variant="outline" and semantic color class per status.
**States:**

| Status | Classes | Label |
|--------|---------|-------|
| `pending` | `bg-neutral-100 text-neutral-500 border-neutral-200` | Queued |
| `running` | `bg-blue-100 text-blue-700 border-blue-200` | Researching |
| `done` | `bg-green-100 text-green-700 border-green-200` | Done |
| `failed` | `bg-red-100 text-red-700 border-red-200` | Failed |

### ProgressCounter
**Location:** inline within `FirmResearchStatus` (or a small sub-component)
**Pattern:** Text label "N / 7 topics complete" (text-xs, text-neutral-500) paired with a shadcn `Progress` bar showing `(N/7) * 100` value. Only visible while status is `running`. Hidden when status is `done`, `failed`, or `pending`.

### StalenessIndicator
**Location:** `src/components/research/staleness-badge.tsx`
**Pattern:** shadcn `Badge` variant="outline". Two states:
- Stale (lastResearchedAt null OR > 7 days ago): `bg-amber-100 text-amber-700 border-amber-200` label "Stale"
- Fresh (lastResearchedAt within 7 days): `bg-green-50 text-green-600 border-green-100` label "Researched {relative time}" (e.g. "2 days ago")
**No badge rendered** when firm has never been configured for research (CH number absent).

### LastResearchedTimestamp
**Location:** Column in the firms table, or tooltip on `StalenessIndicator`
**Pattern:** `text-xs text-neutral-400` showing the absolute date ("14 Jun 2026") as a tooltip on the staleness badge. Never shown as standalone text — always paired with the badge.

## Interaction Contracts

### Research Trigger Flow

1. User clicks "Run Research" button in the firm row.
2. Button transitions immediately to spinning state ("Researching…"), disabled. Toast appears: "Starting research for {firmName}…" with description "This takes ~20 seconds per firm."
3. Server action enqueues job and fires the fire-and-forget POST to `/api/research/run`. Returns `jobId`.
4. Client begins polling `GET /api/research/status/{jobId}` every 2.5 seconds.
5. Progress counter updates: "N / 7 topics complete" with progress bar advancing.
6. On `done`: button resets to idle. Toast replaces loading toast: "Research complete — {N} findings written for {firmName}." Staleness badge transitions to "Fresh". Progress counter hides.
7. On `failed`: button resets to idle. Toast: "Research failed for {firmName}" with description from `jobs.errorMessage`. JobStatusBadge shows "Failed". Progress counter hides (showing partial count is acceptable).

**Polling stops** when job status is `done` or `failed`.

### Staleness Display

- Firms table gains a "Research" column (inserted between "Capabilities" and "CH Number" columns) showing: `StalenessIndicator` + `ResearchTriggerButton` grouped together.
- The "Research" column replaces the current empty "Refresh" spacing in the actions area — the CH/CF/FTS structural refresh (`FirmRowRefresh`) and the AI research trigger (`ResearchTriggerButton`) are both visible in the actions cell but are visually distinct (different icons, different tooltips).

### Empty State (no findings yet)

The firms table row shows the `StalenessIndicator` in "Stale" state from the moment a firm is added (since `lastResearchedAt` is null). The trigger button is always visible and enabled (unless CH number is missing). There is no separate "empty state" treatment in Phase 2 — the staleness badge communicates "not yet researched" implicitly.

## Copywriting Contract

| Element | Copy | Source |
|---------|------|--------|
| Primary CTA (research trigger button tooltip) | "Run AI research for {firmName}" | Prescribed — phase goal |
| Primary CTA (running state tooltip) | "Researching… ({N}/7 topics)" | Prescribed — phase goal |
| CTA disabled (no CH number) | "Add a Companies House number before running research" | Prescribed — guards DATA-04 |
| Loading toast heading | "Starting research for {firmName}…" | Consistent with Phase 1 loading toast pattern |
| Loading toast description | "This takes around 20 seconds. Progress updates as topics complete." | Prescribed |
| Success toast heading | "Research complete" | Prescribed — positive, specific |
| Success toast description | "{N} findings written for {firmName}." | Prescribed — gives user a count to verify something happened (CONTEXT.md: "N findings written so user knows something happened") |
| Error toast heading | "Research failed for {firmName}" | Consistent with Phase 1 `"Couldn't load procurement data"` pattern — identifies which firm |
| Error toast description | "{jobs.errorMessage}" falling back to "The research worker stopped unexpectedly. Try again, or check the app logs." | Provides cause if known, actionable fallback if not |
| Partial failure note (in-row) | Job status badge: "Failed" with tooltip "Research stopped after {N}/7 topics. Partial findings saved. Click to re-run." | Prescribed — D-05: partial findings are retained, re-trigger is the resolution |
| Staleness badge — stale state | "Stale" | Concise, consistent with dashboard conventions |
| Staleness badge — fresh state | "Researched {N} days ago" (1 day: "Researched today") | Human-readable relative time |
| Staleness badge — never researched | "Not researched" | Explicit absence — consistent with RES-05 "silence is never returned without a reason" |
| Progress counter | "{N} / 7 topics complete" | Matches CONTEXT.md D-06 exactly |
| Job status badge labels | "Queued" / "Researching" / "Done" / "Failed" | Plain English, not technical enum values |

**No destructive actions** are introduced in Phase 2. No AlertDialog or confirmation modals are needed.

## Accessibility

- All interactive elements (trigger button, status badge with tooltip) have `aria-label` or visible text.
- The progress bar uses the shadcn `Progress` component which renders a `role="progressbar"` with `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax="100"`.
- The `ResearchTriggerButton` uses `aria-label="Run AI research for {firmName}"` (updates to `aria-label="Research running for {firmName}"` in the running state).
- Toast notifications (Sonner) are announced by screen readers via `role="status"` — no additional ARIA handling required.
- Spinning icon uses `aria-hidden="true"` — the button's `aria-label` carries the semantic state.
