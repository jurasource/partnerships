<objective>
Build the citation-grounded research synthesis engine: a Tavily web-search client behind a swappable interface, the Zod Finding schema that enforces the citation invariant in code, the bounded grounding-context builder, the prompt builders, and the per-firm research worker that synthesises one Zod-validated finding per (firm × topic) via the Vercel AI SDK — falling back to an explicit "not found" sentinel rather than ever storing an unsourced or LOW-confidence claim.

Purpose: This is the core of Phase 2 and the highest-risk part of the project. RES-03 (mandatory citations), RES-04 (structured vs AI provenance), and RES-05 (explicit not-found) are all enforced here in code, not by prompt. The worker is dependency-injected (search client passed in) so its data-integrity invariants are unit-testable without live API keys.

Output: A working `runResearchWorker(firmId, jobId, searchClient)` that, given a firm with cached CH/OCDS data, writes exactly one citation-complete findings row per topic. Wave 2 wires it to a triggerable route; Wave 3 adds the UI.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| worker → Anthropic API | Outbound; ANTHROPIC_API_KEY is a server-only secret, read from process.env, never reaches a client component |
| worker → Tavily API | Outbound; TAVILY_API_KEY is a server-only secret; only firm name/topic strings (not user-controlled host/scheme) reach fetch |
| AI model output → findings table | The model's output is UNTRUSTED text crossing into persisted, user-trusted data; the schema + gates are the boundary control |
| npm registry → project deps | Supply-chain boundary for the two new packages |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | TAVILY_API_KEY / ANTHROPIC_API_KEY | mitigate | Both clients/worker start with `import "server-only"`; keys read via env-guard functions, never hardcoded, never imported into client components (Phase 1 T-01-08 pattern) |
| T-02-02 | Tampering | AI model output written to findings | mitigate | FindingSchema (.min(1) citation fields, enum without LOW) validates every output before insert; NOT_FOUND_SENTINEL substituted on validation failure — no unsourced claim is ever persisted (RES-03/RES-05, E1/E2) |
| T-02-03 | Spoofing | Fabricated/hallucinated sourceUrl | mitigate | Citation-origin gate: a MEDIUM finding whose sourceUrl is not a member of the retrieved Tavily result URLs is coerced to the not-found sentinel (E4) |
| T-02-04 | Denial of Service | Unbounded model output / runaway cost | mitigate | maxOutputTokens:512 on every generateText call; sequential (not parallel) topic loop bounds concurrent API calls (AI-SPEC §4b) |
| T-02-SC | Tampering | npm installs (`ai`, `@ai-sdk/anthropic`) | mitigate | Task 1 blocking-human checkpoint verifies both packages against npmjs.com before install; both treated [ASSUMED] per fallback policy (no phase RESEARCH.md audit table) |
</threat_model>
